# x86_64 port

> **Status:** Partial — the port is the most complete: BIOS/UEFI boot, boot
> protocol v1, SMP, paging, ring-3 user processes and storage work. It still
> has driver-boundary and multi-Thread/parallel-Flow gaps.
>
> **Scope:** x86_64-specific boot, CPU, memory, interrupt and user-mode
> mechanisms. Shared semantics are in the concept and kernel documents.

## 1. Boot paths

### BIOS

```text
LBA 0       512-byte MBR boot sector
LBA 1..32   stage2 (CHS loader)
LBA 33      image header
LBA 34..    flat kernel
...         ramdisk
LBA 2048..  EFI System Partition (hybrid image only)
```

- The MBR loader reads stage2 with CHS `INT 13h`.
- Stage2 loads the flat kernel and ramdisk, builds a 1 GiB identity map with
  2 MiB pages, enters long mode and jumps to `0x4000000` (64 MiB).
- Stage2 fills `fboot_info` at physical `0x5000` and passes it in `RDI` with
  `RSI = FINTE_BOOT_MAGIC`.
- The BIOS path uses VGA text and COM1.

### UEFI

- Firmware loads `EFI/BOOT/BOOTX64.EFI`.
- The loader opens the ESP, reads `KERNEL.BIN` and `RAMDISK.BIN`, allocates a
  36 MiB kernel region at 64 MiB, and fills the v1 `fboot_info` structure:
  memory map, ACPI pointer, ramdisk module and GOP framebuffer.
- It calls `GetMemoryMap` and `ExitBootServices`, then clears the firmware
  pointers, Block I/O and ConIn fields with `fw_services = 0`.
- The kernel no longer calls firmware services on the x86 UEFI path. The GOP
  framebuffer remains valid memory; input is serial and PS/2.

### ISO

`make images` builds an El Torito ISO:

- BIOS entry: a 288 KiB hard-disk-emulation image with a small MBR partition
  whose CHS geometry fits below the EBDA;
- UEFI entry: a 16 MiB FAT16 ESP image with `BOOTX64.EFI`, `KERNEL.BIN` and
  `RAMDISK.BIN`.

## 2. CPU and SMP

- Long mode, flat data selectors, per-CPU GDT/TSS.
- APs start through an INIT/SIPI trampoline at physical `0x8000`.
- Each AP claims a logical CPU slot, installs its GS base, builds a GDT/TSS
  lazily on first Thread switch, and enters `finte_sched_ap_run()`.
- Up to 8 CPUs (`FINTE_MAX_CPUS`).
- Per-CPU run queues, run-queue locks, LAPIC timers, wake IPIs and page/stack
  caches.
- Primary Thread affinity and migration are implemented; the public migrate
  API still takes a Flow.
- Work stealing is present in code but currently disabled (`if (!f && 0)`).

## 3. Memory

- Kernel linked at 64 MiB and built as a flat binary for the BIOS path.
- 1 GiB identity map with 2 MiB pages.
- 32 MiB static kernel heap in `.bss`, used only as the no-boot-info fallback.
- `hal_pages_alloc()` uses the shared bitmap PMM when the boot memory map is
  available; flow stacks are freed back to the PMM. The static heap keeps bump
  allocation plus page/stack caches for fallback boots.
- User processes use private PML4s. The low 4 GiB are mapped supervisor-only;
  user code/data live above 4 GiB.
- User layout: `FPROC_USER_BASE` 4 GiB, stack top 4 GiB + 64 MiB, shared page
  4 GiB + 128 MiB, Arena range 4 GiB + 192 MiB, mmap range 4 GiB + 256 MiB,
  limit 5 GiB.
- The shared process core builds private PML4s through `fproc_arch_ops`. Code
  pages are RX, data/stack/shared/arena/mmap pages are RW-NX; `EFER.NXE` is
  enabled per CPU and PTE bit 63 carries NX.
- User pages are non-global and CR3 is reloaded on every root switch, so a CPU
  that leaves a space drops its user TLB entries; unmaps do local `invlpg`.
  Address spaces are refcounted and Flow-owned, with release deferred until
  after the scheduler-root switch.
- Anonymous and file-backed private `mmap`/`munmap` are demand-paged;
  `mincore` reports residency and `MADV_PAGEOUT` evicts to a raw swap block
  device, with fault-in restoring the original bytes.

## 4. Interrupts and timers

- IDT with exception and IRQ gates.
- PIC remap and PIT timer on the BSP.
- LAPIC timer on APs, calibrated, with TSC-deadline when available.
- Timer preemption and sleeper wakeup.
- Wake IPIs for parked CPUs.
- Firmware IDT switching for UEFI Boot Services.
- Three-strike watchdog.

## 5. User mode

- Ring 3 through GDT/TSS and `int 0x80`.
- The user layer is the shared `src/core/process.c`: ELF loading, a dynamic fd
  table with shared open-file descriptions and dup/dup2/fcntl,
  `mmap`/`munmap` (anonymous and file-backed private), `fork`, blocking
  `waitpid` with reaping, `exec`, signal masks/pending sets/default actions,
  SIGSTOP/SIGCONT job control, process groups with `setpgid`/`getpgrp` and
  group `kill`/`waitpid`, SIGALRM and CPU-time interval timers, user-to-user
  cap transfer, a capability service registry, fixed-address ET_DYN loading
  and the demo orchestration.
- Per-process PML4, four-page user stack, fixed shared page, scoped Arena
  mappings and fork-inherited fds.
- User copy-in/out validates the user window, page presence and write rights.
- User faults kill the process and record a watchdog strike.
- The ring-3 syscall set remains a demo ABI, not the native ABI.

## 6. Drivers

- Legacy ATA PIO for BIOS.
- AHCI DMA for q35/UEFI.
- UEFI firmware Block I/O fallback is retained in code only for a producer
  that keeps `fw_services`; the current loader exits and disables it.
- PS/2 and COM1 input; firmware ConIn is used only when `fw_services` is set.
- VGA text and GOP framebuffer consoles.
- Disk manager and lfc1/ext4/NTFS in the kernel.

## 7. Known gaps

- Work stealing disabled.
- x86 UEFI has no native USB-HID keyboard driver; USB-only laptops need one
  before the shell is usable without serial/PS/2.
- No IOMMU or DMA isolation.
- The process ABI is a demo subset: copy-on-write fork, capped anonymous
  mappings, signal masks/pending sets with SIGUSR1/2/SIGCHLD handlers,
  default SIGTERM/SIGINT/SIGSEGV, basic SIGSTOP/SIGCONT job control,
  process groups via setpgid/getpgrp and group kill/waitpid, SIGALRM and
  CPU-time `alarm`/`setitimer` timers.
- The x86 process ABI suite is pinned to the BSP. Simultaneous fork/sleep/
  migration is not stress-tested; arm64 covers the 4-CPU ABI path.
- No multi-Thread or Parallel Flow model.
- No user-space driver framework.
- No physical hardware qualification.

## 8. Test evidence

- `make qemu-test`: BIOS boot, boot protocol v1 with E820 map, CLI.
- `make qemu-uefi-test`: OVMF boot, v1 memory map/ACPI/module, `fw=0`, CLI.
- `make abi-test`: 1-CPU process ABI suite (fd/mmap/filemmap/cow-fork/waitpid/
  exec/signal/sigset/job/cap/churn/blocked abort) and PTE RX/RW-NX checks.
- `make qemu-disk-test`: ATA PIO and three filesystems.
- `make qemu-uefi-disk-test`: AHCI and three filesystems.
- `preempt`, `smp`, `procs`, `services`: scheduling, SMP, ring-3 isolation.
- `make images`: BIOS/UEFI IMG and ISO, locally booted under SeaBIOS and OVMF.
